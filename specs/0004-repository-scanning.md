# 0004 — Repository Scanning & File Filtering

## Goal

Enumerate the repository's files (`discover_files`) and classify each one as `analyze`, `reduced_weight` or `ignored` with an explicit reason (`filter_files`), so that only informative source files reach chunking and every exclusion is auditable in the report.

## Scope / Non-goals

- **In scope:** file enumeration, `.gitignore` handling via `pathspec`, denylist rules, generated/vendored/minified/binary detection, priority ordering, hard pre-scan limits.
- **Non-goals:** reading Git history (spec 0005), chunk splitting (spec 0006).

## Contracts

### `FileInventory` (output of `discover_files`)

```python
class FileInventory(BaseModel):
    total_files: int
    total_bytes: int
    entries: list[FileEntry]        # FileEntry: relpath, size_bytes, extension

class ClassifiedFile(BaseModel):    # output of filter_files, one per inventory entry
    relpath: str
    size_bytes: int
    line_count: int | None          # filled for analyze/reduced_weight only
    language: str | None            # extension-based guess
    classification: Literal["analyze", "reduced_weight", "ignored"]
    reason: str                     # rule id that decided, e.g. "denylist:node_modules"
    priority: int                   # scoring order; lower = scored first
```

### Enumeration rules (`discover_files`)

1. Walk from `repo.root` using `git ls-files` output when available (tracked files only) plus untracked-but-not-ignored files; fallback to `os.walk` if git listing fails.
2. `.git/` is always excluded.
3. If `request.respect_gitignore` is true, apply `.gitignore` patterns via `pathspec` (`GitWildMatchPattern`), including nested `.gitignore` files.
4. **Hard pre-scan limits** (fatal `REPOSITORY_TOO_LARGE`): `max_repo_files = 50_000`, `max_repo_bytes = 2 GiB` (configurable, spec 0012).

### Classification rules (`filter_files`) — evaluated in order, first match wins

| # | Rule | Result |
|---|------|--------|
| 1 | Path matches directory denylist: `node_modules/`, `dist/`, `build/`, `out/`, `.next/`, `coverage/`, `.terraform/`, `vendor/`, `third_party/`, `.venv/`, `venv/`, `__pycache__/`, `.idea/`, `.vscode/` | `ignored` (`denylist:<dir>`) |
| 2 | Lockfiles: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `uv.lock`, `poetry.lock`, `Cargo.lock`, `go.sum`, `Gemfile.lock`, `composer.lock` | `ignored` (`lockfile`) |
| 3 | Binary: first 8 KiB contains a null byte, or extension in binary list (images, archives, fonts, executables) | `ignored` (`binary`) |
| 4 | Minified: filename matches `*.min.*`, or average line length > 300 chars over first 50 lines | `ignored` (`minified`) |
| 5 | Generated markers: first 20 lines match `(?i)(do not edit|@generated|code generated by|autogenerated|swagger|openapi-generator|protoc-gen)` , or path matches `**/migrations/**`, `*_pb2.py`, `*.pb.go`, `*.generated.*`, `**/generated/**` | `ignored` (`generated:<marker>`) |
| 6 | Not a recognized text/source extension (extension→language map maintained in code; includes py, ts, tsx, js, jsx, go, rs, java, kt, rb, php, cs, c, cpp, h, sql, sh, …) | `ignored` (`not_source`) |
| 7 | Config/data formats: json, yaml, toml, ini, csv, md | `reduced_weight` (`low_signal_format`) |
| 8 | File > 200 KiB or > 5000 lines | `reduced_weight` (`oversized`) |
| 9 | Otherwise | `analyze` |

`reduced_weight` files are chunked and scored normally but weighted at 0.5 in aggregation (spec 0008).

### Priority ordering

`priority` sorts files for scoring so budget cuts (spec 0003) drop the least informative files last:
`analyze` before `reduced_weight`; within each class, primary source languages first, larger line counts first, most recent commit date (from spec 0005, when available) as tiebreaker. If `max_files_analyzed` is exceeded, trailing files are reclassified `ignored` (`budget:max_files`) — recorded, not silently dropped.

## Invariants

- **INV-0004-01:** scanning performs no writes anywhere inside `repo.root`.
- **INV-0004-02:** every inventory entry appears in exactly one classification with a non-empty `reason`.
- **INV-0004-03:** symlinks are never followed outside `repo.root` (resolve + prefix check, spec 0010); escaping symlinks are `ignored` (`symlink_escape`).
- **INV-0004-04:** classification is deterministic: same tree ⇒ same result.

## Error cases

| Case | Behavior |
|------|----------|
| Pre-scan limits exceeded | fatal `REPOSITORY_TOO_LARGE` |
| Unreadable file (permissions) | `ignored` (`unreadable`), recoverable |
| Broken symlink | `ignored` (`broken_symlink`) |
| Zero `analyze`/`reduced_weight` files after filtering | fatal — "nothing to analyze" (mapped to `INVALID_INPUT` at the boundary) |

## Acceptance criteria

- **AC-0004-01:** fixture repo with `node_modules/`, a lockfile, a minified file, a generated client, a binary and normal sources → each classified per the table, with correct reasons.
- **AC-0004-02:** `respect_gitignore=false` includes gitignored files; `true` excludes them.
- **AC-0004-03:** a symlink pointing outside the repo is ignored with `symlink_escape`.
- **AC-0004-04:** exceeding `max_repo_files` raises `REPOSITORY_TOO_LARGE`.
- **AC-0004-05:** priority ordering matches the documented sort on a mixed fixture.
